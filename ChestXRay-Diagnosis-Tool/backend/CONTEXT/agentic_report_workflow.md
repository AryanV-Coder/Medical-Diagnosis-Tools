## What this feature does

Given a disease name, probability, and positive flag (from inference), this module uses
LangGraph to run a two-agent loop: a **Scribe** agent writes a clinical radiology report
grounded in RAG context, and an **Auditor** agent checks it against a safety checklist.
If the Auditor fails the report, it sends specific feedback back to the Scribe, which
rewrites only the flagged parts. The loop runs until PASS or until 3 iterations.
The final output is a dict with `raw_text` and a `sections` dict for the frontend editor.

## State schema — `ReportState` (TypedDict)

```python
class ReportState(TypedDict):
    disease:     str       # e.g. "Cardiomegaly"
    probability: float     # e.g. 0.8174
    positive:    bool      # True/False
    context:     str       # RAG chunks (fetched by Scribe on first run, reused after)
    draft:       str       # current report markdown text (Scribe writes, Auditor reads)
    feedback:    str       # Auditor's feedback; empty string "" means approved
    final:       str       # finalized report text (set by Auditor on PASS)
    sections:    dict      # parsed sections dict (set by Auditor on PASS)
    iterations:  int       # safety counter; max 3 iterations enforced
```

## Graph structure

```
Entry: scribe
  │
  ▼
auditor
  │
  ├─ feedback == "" OR iterations >= 3  →  END
  └─ feedback != ""                     →  scribe  (loop back)
```

Built as:
```python
graph = StateGraph(ReportState)
graph.add_node("scribe",  scribe)
graph.add_node("auditor", auditor)
graph.set_entry_point("scribe")
graph.add_edge("scribe", "auditor")
graph.add_conditional_edges("auditor", route_after_auditor)
report_graph = graph.compile()
```

---

## Node: `scribe(state) -> ReportState`

**First run** (`state["feedback"] == ""`):
- Calls `fetch_context(disease)` to get RAG context string
- Sends a structured prompt to Gemini asking for a 4-section report

**Subsequent runs** (`state["feedback"] != ""`):
- Reuses `state["context"]` (no second RAG call)
- Sends a rewrite prompt showing the original draft + auditor feedback

Required output format from LLM (enforced via prompt):
```
## FINDINGS
...
## CLINICAL IMPRESSION
...
## RECOMMENDATIONS
...
## DISCLAIMER
...
```
- Updates state fields: `context`, `draft`, `feedback` (reset to ""), `iterations` (+1)

---

## Node: `auditor(state) -> ReportState`

Checklist checked by the Auditor via LLM prompt:
1. Has a `## DISCLAIMER` stating it must be reviewed by a licensed radiologist?
2. Correctly names the detected disease?
3. Has `## RECOMMENDATIONS` with at least 2 actionable steps?
4. If disease is `Effusion`, does it mention TB or NTEP screening?

**On PASS:**
- Calls `parse_sections(state["draft"], state)` to build the sections dict
- Sets `state["final"] = state["draft"]`, `state["sections"] = sections`, `state["feedback"] = ""`

**On FAIL:**
- Extracts feedback lines from LLM response
- Sets `state["feedback"] = feedback` (non-empty → Scribe will rewrite)

---

## `parse_sections(report: str, state: ReportState) -> dict`

Splits the flat markdown report into named sections using regex on `## HEADER` markers.
Returns a dict with these exact keys (used directly by the frontend editor):

```python
{
    "title":           {"key": "title",           "title": "Report Title",        "content": "RADIOLOGY REPORT — AI ASSISTED DRAFT", "editable": True},
    "patient_info":    {"key": "patient_info",    "title": "Patient Information", "content": "<auto-generated from state>",           "editable": True},
    "findings":        {"key": "findings",        "title": "Findings",            "content": "<extracted from ## FINDINGS>",          "editable": True},
    "impression":      {"key": "impression",      "title": "Clinical Impression", "content": "<extracted from ## CLINICAL IMPRESSION>","editable": True},
    "recommendations": {"key": "recommendations", "title": "Recommendations",     "content": "<extracted from ## RECOMMENDATIONS>",   "editable": True},
    "disclaimer":      {"key": "disclaimer",      "title": "Disclaimer",          "content": "<extracted from ## DISCLAIMER>",        "editable": False},
}
```
The `patient_info` content is auto-generated from state (disease, probability, positive, UTC datetime) — not extracted from LLM text.

## Public function called by `main.py`

```python
def generate_report(disease: str, probability: float, positive: bool) -> dict:
    result = report_graph.invoke({
        "disease": disease, "probability": probability, "positive": positive,
        "context": "", "draft": "", "feedback": "", "final": "", "sections": {}, "iterations": 0,
    })
    return {
        "raw_text": result["final"],
        "sections": result["sections"],
    }
```
- **Synchronous and blocking** — `main.py` must call it via `asyncio.to_thread()`.
- `result["final"]` is empty string if the graph somehow ends without a PASS — handle this defensively in future.

## Editing guidance for AI

| Scenario | What to change |
|---|---|
| Add a new checklist item to Auditor | Edit the numbered checklist in `auditor()` prompt string |
| Change report sections (add/remove) | Update Scribe prompt headers AND `parse_sections()` regex AND the returned dict keys |
| Change LLM model | Update `model=` in `ChatGoogleGenerativeAI` instantiation |
| Change max retry iterations | Update the `>= 3` guard in `route_after_auditor()` |
| Make report generation async | Replace `llm.invoke()` with `await llm.ainvoke()` and convert nodes to async |
| Add a new disease-specific Auditor rule | Add a numbered item to the Auditor checklist prompt with `if disease is X` condition |

---

## Do NOT change
- The exact section header strings (`## FINDINGS`, `## CLINICAL IMPRESSION`, `## RECOMMENDATIONS`, `## DISCLAIMER`)
  without updating `parse_sections()` regex patterns — they are tightly coupled.
- The `ReportState` TypedDict keys without updating ALL nodes and `generate_report()` initial state.
- The `"feedback": ""` reset in `scribe()` — it is what signals PASS to `route_after_auditor()`.
